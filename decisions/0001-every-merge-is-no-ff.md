# Every merge into the integration branch is `--no-ff`, single-commit branches included

A branch holding one commit still merges `--no-ff`, so GitHub's commit list (flat, date-sorted, no first-parent view) shows its subject twice: the merge, then the commit. The tracker reads that merge commit: `tracker land` (`branch_in`) finds a merged ticket's range by the merge whose second parent is the ticket's tip. A tip merged with no merge commit of its own gets no range, since git cannot tell it from a branch that committed nothing, so a fast-forwarded ticket would land with no range recorded. Fast-forwarding single-commit branches would otherwise lose nothing for mining the history (the commit keeps its `Workflow-stage:` trailer, `--first-parent` still shows one line per ticket), but it would add an exception to an "always" rule and a branch in `branch_in` that guesses a range (`tip^..tip`) which holds only while the rule is followed. A cleaner GitHub list is not worth either.
