# Every merge into the integration branch is `--no-ff`, single-commit branches included

A branch holding one commit still merges `--no-ff`, so GitHub's commit list (flat, date-sorted, no first-parent view) shows its subject twice: the merge, then the commit. `dispatch` reads that merge commit: `range_of` finds a landed ticket's range by the merge whose second parent is the ticket's tip, and dies when no merge brought the tip in. Fast-forwarding single-commit branches would also lose nothing for mining the history (the commit keeps its `Workflow-stage:` trailer, the ticket keeps its range in its frontmatter, `--first-parent` still shows one line per ticket), but it would add an exception to an "always" rule and a branch in `range_of` that guesses a range (`tip^..tip`) which holds only while the rule is followed. A cleaner GitHub list is not worth either.
