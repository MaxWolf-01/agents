The interface, sketched

Sample invocations with the output they would print. The body of a ticket stays prose the agent writes in the file; the commit hook runs tracker check over it.

sketch: the parser ticket's worker designs the real interface

Filing writes the skeleton and prints the path; the agent writes the Brief and the rest into it.

$ tracker new ticket-parser-and-commit-check --parent ticket-file-contract --priority 1 --size L
agent/tickets/ticket-parser-and-commit-check.md

A status change says what it moved from. A transition the rules forbid is refused with the reason: done is written only once the accepted branch is merged.

$ tracker set scripts-read-tickets-through-parser status=review
scripts-read-tickets-through-parser: claimed → review

$ tracker set scripts-read-tickets-through-parser status=done
tracker: refused: scripts-read-tickets-through-parser review → done: ticket/scripts-read-tickets-through-parser
is not merged into ticket-file-contract; done follows the user's accept and its merge

Q6: how far does the parser reach?

(a)

The parser only reads and checks. check, one field, the whole tracker as data, a ticket's context. Every write stays a hand edit that follows the skill's prose.

buysthe smallest parser; the child ticket stays size M.

coststhe transition rules stay prose; the frontier is still derived by hand every tick; retire stays a recipe of five commands in prose; dispatch keeps its own sed writer beside the parser's reader, so status still has two owners.

➡ (b)

One tracker command owns every mechanical operation, reads and writes. The skill keeps the judgment and points at tracker --help. board stays its own command and reads through tracker; dispatch's claim and flips call it.

buysthe transition rules (a ticket in review unblocks nothing, done only after the accept) are enforced where they are written, not read in prose; retire becomes one command; the frontier becomes a query; every write goes through the code that reads, so P2 covers writes too. PRINCIPLES.md §1: "a script that does the thing beats a paragraph of prompt about it".

coststhe parser ticket grows from M to L; one more --help every agent reads; the prose has to name commands, and a renamed command is a prose edit.

(c)

(b), and the body too: commands to add a question, a comment, an assumption, tick a criterion.

buysno hand edit ever touches a ticket file.

costsagents already edit markdown well, and the commit hook catches a malformed body at commit; every section command widens the interface for little.

5

What changes in the three child tickets under (b)

  • ticket-parser-and-commit-check

    Becomes the tracker command: reads, writes, check, and the pre-commit hook. Size M → L.

  • scripts-read-tickets-through-parser

    Dispatch and the board call tracker for writes as well as reads: claim, the review and landing flips, the diff: range. No set_status left in dispatch.

  • skills-and-glossary-speak-one-ticket-kind

    Shrinks the tracker skill to the judgment plus one pointer to tracker --help; the worker contract's "set status: review" becomes the command.
