Q1: which branch a ticket file is committed on

The same run drawn both ways: parse-ticket-files is filed, claimed, built, flipped to review, accepted, and later the parent closes out and merges. Only where the ticket-file commits land differs.

Slugs as ids

The filename is the id, and parent: and blocked-by: both name it. That leaves one form of reference where there are three today.

before: three forms, from the live tracker 
# session-page/04-stop-hook.md
blocked-by: [02, 03]            # number in this dir
# workers-in-flight.md
blocked-by: [board-orients/05]  # feature/number
# a standalone ticket's slug
blocked-by: [one-flow-open-rulings]
after: one form 
# agent/tickets/scripts-on-parser.md
parent: ticket-file-contract
blocked-by: [parse-ticket-files]

# agent/tickets/workers-in-flight.md
blocked-by: [sessions]

Why not global numbers. Two branches that each file "the next number" both take 0043 and collide when they merge. Two slugs collide only when two tickets carry the same name.

What it costs. Renaming a ticket means repointing every reference to it. The parser reports a dangling parent or blocked-by with its file and line.

to ruleThe filename slug is a ticket's only id, used by parent: and blocked-by:.

The Parent glossary entry

One entry comes into CONTEXT.md, and four you ruled out leave it. The struck text is what each says today.

added

Parent:

The ticket another ticket is part of. The child reads the parent's body as its context, cuts its branch from the parent's, and the parent is done once every child is done and its own review is ruled.

Avoid: epic, feature, spec, story

removed

Feature:

The unit the tracker holds one spec for: one directory, its spec, its tickets, whatever the size. Not the product sense; a big design splits into sibling features, never nested ones.

Spec:

The work order for one feature: as much design as one gate can confirm.

Standalone ticket:

A ticket with no spec: work that needs no design round, or a decision filed for later.

Gate:

The point where a spec is confirmed and reads cold from then on.

to ruleParent is added with the text above; Feature, Spec, Standalone ticket and Gate are removed.
4 · my call

Close-out at every parent

The steps a feature runs today once it has no ticket left to start (/mx:dispatch, Stop or sleep) run at every ticket that has children, before it merges into its own parent's branch. The pass over the whole output you asked for is step 2 at the top-level ticket. In the figure, scripts-on-parser is given two children of its own, which the running example does not have, to show a third level.

Cost. Each close-out adds a review, a harden run and a debrief. Most trees here are one or two levels deep, so it is paid once or twice per piece of work.

to ruleEvery ticket with children runs the close-out before it merges into its parent's branch.

Inherited properties

A property is stated once, on the ticket it holds for. Every descendant reads it through its ancestors instead of carrying a copy. The example property is the one drafted in question 5 of ticket-file-contract.md.

before: stated in the spec, stamped onto every child 
# spec.md
## Properties
- P1 Text a writer put in a machine-read section
  is read whole or refused with its line named,
  never dropped.

# 01-parse-ticket-files.md, 02-…, 03-…: each one
## Acceptance criteria
- [ ] Property P1, reviewed: text in a machine-read
      section is read whole or refused …

property-coverage checks that every spec property reached some ticket's criteria.

after: stated on the parent, read through ancestry 
# ticket-file-contract.md
## Properties
- P1 Text a writer put in a machine-read section
  is read whole or refused with its line named,
  never dropped.

# parse-ticket-files.md
# nothing stamped; the reviewer reads this ticket
# plus ticket-file-contract.md and checks P1

# cited elsewhere as
ticket-file-contract#P1

property-coverage checks one thing: every property disposed as executable has a check under tests/properties/.

to ruleProperties are inherited through parent; to-tickets stops stamping them; a property is cited as <slug>#P<n>.

Migration script

A one-off script, run once after board-orients merges. Each spec.md becomes <dir>.md, the parent. Each NN-slug.md becomes <slug>.md with parent: set and blocked-by rewritten to slugs. Collision rule: where two tickets would take the same slug, each gets its parent's slug as a prefix. The real tree has one possible collision: board-orients and figures-and-demos each have a whole-feature-review ticket.
