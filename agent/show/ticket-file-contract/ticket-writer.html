Who writes a ticket file, and where it lives

Today the worker writes its own ticket file on its code branch. Three problems follow from that one habit; the proposal moves every ticket write to the orchestrator.

2

The proposed shape: the orchestrator is the only writer

callThe orchestrator and the sessions working with you are the only writers of ticket files; the worker reports to a file the runner names.

3

Where ticket files are committed, then

Round 2's Q1 put a child ticket's file on its parent ticket's branch so the worker's review flip had a branch to land on. With the worker out of ticket files, that reason is gone.

callTicket files are committed in the tracker's own checkout, on the branch it has out, never on a code branch.

4

How dispatch finds the tickets

Dispatch already runs in the code repo's checkout: it merges ticket branches there. So the code repo is known; what dispatch lacks when the tickets live elsewhere is where the tracker is. A code repo names its tracker, and by default that is its own agent/tickets/.

call(a): git config mx.tracker in the code repo's clone; unset means its own agent/tickets/.
