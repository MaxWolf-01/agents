Planning too big for one session: a shared map of decision tickets.

Chart the map once, then loop: each lap is a fresh session that claims one open question, resolves it, and records the decision on the map and in the spec draft. Sessions come and go; the map and the draft accumulate. When no tickets remain and no fog is specifiable, the way is clear: the last session confirms the spec, and only then does building start. A repo can run several maps (efforts) at once.
