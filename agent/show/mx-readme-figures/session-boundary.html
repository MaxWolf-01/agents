mx workflow · grilling across sessions

Planning that spans sessions: the spec carries the design, decision tickets carry the open questions.

Every grilling writes the spec round by round, so a session boundary is not a fork in the flow. A session that ends with questions open files them as decision tickets; the next session claims one, grills it, and rewrites the spec sections it names. Whether the frontier drains in one session or twelve is discovered, not declared; when it is empty, the gate confirms the spec and building starts.
