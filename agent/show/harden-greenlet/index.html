harden and greenlet

What breaks, what v0.1.43 does about it, and the shape that needs no detector and no per-project config. Every number below is from a run on the yapit and memex clones today.

What breaks

SQLAlchemy's async engine runs on greenlet, a library that switches stacks under Python's tracer. coverage.py's default tracer loses the frame at the switch, so every line after an await into the engine is recorded as never run. It does not warn. This is the one test that exercises get_document, as coverage sees it:

1421async def get_document(document_id: UUID, db: DbSession, user: OptionalUser) -> DocumentDetailResponse:


1422    """Get a document. Public docs need no auth; private docs require ownership."""


1423    document = await _get_document_with_optional_auth(document_id, db, user)


1424    is_owner = user is not None and document.user_id == user.id


1425    return DocumentDetailResponse(


1426        id=document.id,

Green: recorded as run. Red: run by the test (replacing line 1424 with raise fails it) and recorded as not run. Across documents.py that is 15 statements, across yapit 19.

Why harden cares: it mutates only covered lines, so those 15 statements get no mutants and the report lists them as "changed lines nothing runs". A wrong map is worse than no map.

What is there now (v0.1.43)

The fix chosen was coverage's documented setting, put in the project: [tool.coverage.run] concurrency = ["thread", "greenlet"]. Because coverage does not warn when it is missing, harden then had to detect the missing setting, and because harden runs under uv run --with, which layers its own packages over the project's, import greenlet cannot tell whose greenlet it is. So:

  • project_has_greenlet greps uv.lock for name = "greenlet", then globs .venv/lib/python*/site-packages/greenlet.
  • require_concurrency_config reads the project's coverage config and exits with a message telling the project to add the line.
  • Two tests build fake lock files and venvs to check the detector; a PYTHON.md paragraph and a --help sentence tell every project about it.

Three functions and a filesystem sniff exist to prove that a project failed to configure itself for harden. A tool that needs every project set up for it, plus a detector for when it was not, is the wrong shape: the measurement is harden's, so its settings should be harden's.

Where the setting can live

Four places produce the same 12 executed lines in get_document; only the default loses two. Measured on yapit (-k owner_sees_full) and on memex, which does not use greenlet.

The memex column is one coverage pass; harden runs it once per report, then hundreds of mutant runs without coverage, so the flag's three seconds are paid once. The rcfile row is out because it replaces the project's coverage config wholesale (its omit and exclude lines go with it). The sysmon row is the smallest change, and the reason it was dropped ("sysmon and greenlet exclude each other") does not hold: with a project config naming greenlet, coverage warns, falls back to the default core and still records the 12 lines. Its real limit is Python below 3.12, where the sysmon core does not exist and coverage would fall back to the lossy default on a greenlet project.

The shape to build

harden already injects three packages into the project's environment for its run; greenlet becomes the fourth, and the coverage pass names it on the command line. Nothing is read from the project, nothing is refused.

harden.py, run_runner
-    argv = ["uv", "run", "--quiet", "--with", "mutmut~=3.7", "--with", "coverage", "--with", "pytest-cov"]
+    argv = ["uv", "run", "--quiet", "--with", "mutmut~=3.7", "--with", "coverage", "--with", "greenlet"]

-    require_concurrency_config()

-    argv += ["--cov-report=", *test_selection()]

+    argv += [f"--source={','.join(source_paths)}", "-m", "pytest", "-q", *PYTEST_ORDER_ARGS]

Net: about forty lines and two tests deleted, one flag and one --with added, pytest-cov no longer needed. A project with no greenlet pays one slower coverage pass and nothing else. The project's own coverage config is still read by coverage run for everything but concurrency, so omit and exclude lines keep working.

One edge stays open: a project on gevent or eventlet names that in its config, and a fixed --concurrency would override it. When one exists, harden reads the project's list and adds greenlet only if no greenlet-family library is already named; no project of yours does today.
