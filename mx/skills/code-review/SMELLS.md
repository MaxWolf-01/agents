# The smell baseline

A fixed set of code smells (Fowler, _Refactoring_, ch.3, extended) that the Standards axis applies to every diff, even when the repo documents no standards of its own. Two rules bind it:

- **The repo overrides.** A documented repo standard always wins; where it endorses something the baseline would flag, suppress the smell.
- **Always a judgement call.** Each smell is a labelled heuristic ("possible Feature Envy"), never a hard violation — and, like any standard here, skip anything tooling already enforces.

Each smell reads *what it is* → *how to fix*; match it against the diff:

- **Mysterious Name** — a function, variable, or type whose name doesn't reveal what it does or holds. → rename it; if no honest name comes, the design's murky.
- **Duplicated Code** — the same logic shape appears in more than one hunk or file in the change. → extract the shared shape, call it from both.
- **Feature Envy** — a method that reaches into another object's data more than its own. → move the method onto the data it envies.
- **Data Clumps** — the same few fields or params keep travelling together (a type wanting to be born). → bundle them into one type, pass that.
- **Primitive Obsession** — a primitive or string standing in for a domain concept that deserves its own type, including flag `bool`s a two-constructor variant would make self-describing at call sites. → give the concept its own small type.
- **Repeated Switches** — the same `switch`/`if`-cascade on the same type recurs across the change. → replace with polymorphism, or one map both sites share.
- **Shotgun Surgery** — one logical change forces scattered edits across many files in the diff. → gather what changes together into one module.
- **Divergent Change** — one file or module is edited for several unrelated reasons. → split so each module changes for one reason.
- **Speculative Generality** — an abstraction the diff doesn't earn. Either it goes *unexercised* — a parameter every call site passes the same literal for, an interface with one implementer, a config field with one value in the repo, a registry with one entry, a hook nothing calls — or it is used but *doesn't pay for itself*: a knob that doubles the CLI's surface, a strategy layer that multiplies the states to test, an extension point whose interaction with the existing options nobody has enumerated. → collapse it to the case that exists. For the second kind, weigh it out loud: name the cost (API surface, edge cases, states to test, maintenance) against the practical use it buys — a hypothetical or marginal use doesn't pay for it.
- **Message Chains** — long `a.b().c().d()` navigation the caller shouldn't depend on. → hide the walk behind one method on the first object.
- **Middle Man** — a class or function that mostly just delegates onward. → cut it, call the real target direct.
- **Refused Bequest** — a subclass or implementer that ignores or overrides most of what it inherits. → drop the inheritance, use composition.
- **Dishonest Types** — code lying to the type checker: `as any`, non-null assertions on nullables, `T[]` holding nulls. → make the type tell the truth; if it can't, the design is off.
- **Defensive Padding** — guarding against what the system already guarantees: try/except "just in case", null-checks on values no caller can produce, type checks behind a typed signature, the same validation repeated at every hop inward. → validate once at the boundary (user input, external API, deserialization) and trust the invariant after it; delete the rest, and let impossible failures be loud.
- **Narrating Comments** — comments restating what the next line plainly says, or padding it with fluff. → delete; comment only non-obvious behaviour, warnings, complex algorithms.
- **Conversation Residue** — artifact text that only means something to someone who was in the session that wrote it: change narration ("now uses Z", "no longer does W"), decisions-against ("never X", "we don't use Y") where the reader never had X on the table, reviewer reassurance ("correctly handles", "as requested"). Applies to every artifact the diff touches — comments, docstrings, `--help`, UI copy, README, ticket prose. → the artifact states only what is; history belongs in the commit message, the decision in an ADR or the spec's out-of-scope section, the reassurance nowhere.
- **Restated Fact** — one fact stated in two places, where the other place is its home: the code, config, schema, or `--help` that defines it, or the document that owns the concept. The copy may sit right beside the home (a docstring enumerating the enum defined below it, "defaults to 3" beside `retries: int = 3`) or files and repos away (a project doc restating a skill's process, a spec repeating an ADR's decision, a docs page listing defaults that live in a config file, two docs explaining the same concept). Distance makes it worse: a copy beside its home is at least seen when the home is edited; one elsewhere never is. → pick the home, and have every other place point at it, link it, or generate from it. A copy is a cache — it goes stale when the home changes, and then it lies. Three things are not caches: an *illustrative* example, which shows how and never claims to be the full list; a copy for a reader who genuinely can't reach the home (install instructions, a published page), which earns its place by naming that home; and orientation text — a README, an overview — whose job is to hand a cold reader the shape of the thing before they can navigate anywhere, and which stays coarse enough that ordinary changes to the home don't falsify it.
- **Representable Illegal States** — the type permits states the domain forbids: fields that must co-occur but are individually optional, a status field plus booleans that can contradict it, a list that must never be empty. → encode the invariant in the type; make illegal states unrepresentable.
- **Catch-all Match** — a `_`/default arm on a closed set of variants, so adding a variant compiles silently instead of erroring at every site that must handle it. → enumerate the cases; reserve the catch-all for genuinely open sets.
- **Silent Fallback** — a required value replaced by a stand-in rather than a failure: `.get()` where the key must exist, `or 0`, an `except` returning empty. → assert the invariant and let it crash at the point it breaks, not three layers later where the default surfaces as nonsense.
- **Local Inconsistency** — the change introduces a second way to do something the codebase already does one way: a different error-handling shape, a different name for the same kind of thing, a hand-rolled helper sitting next to an existing one. → follow the local convention even where the new way is marginally better; if it is genuinely better, convert the old sites too, or don't introduce it.
- **Compatibility Shim** — code preserving an older shape nobody needs: a deprecated alias kept beside the new name, a version branch, an adapter wrapping the old signature, a "legacy" flag. → change the call sites and delete the shim. If it truly can't be deleted, that's an escalation, not a shim.
- **Bottom-up File** — the file opens with helpers and private functions; the public entry point sits at the bottom, so reading it means starting at the end and jumping upward. → public/main first, helpers below in call order, each unit readable top-to-bottom.
- **Arrow Code** — the real work sits at the deepest indentation, wrapped in success-condition `if`s, with the error cases trailing in `else` branches. → invert the guards, return early on each failure, and leave the happy path flush against the left margin.
- **Pointless Alias** — a local variable that only renames something already reachable (`val = self.cfg.some_val`, then one use of `val`). → use the attribute directly. The inverse also smells: a single expression packing several unnamed sub-computations, or a condition ANDing four clauses — there, *do* name the parts.
- **Unjustified Cleverness** — a construct whose sophistication exceeds its payoff: a metaclass, a decorator stack, a comprehension doing four things, a generic abstraction, where a plain loop or an explicit function would read straight through. → write the boring version. Cleverness has to buy something concrete — a real performance number, a real duplication removed — and the purchase should be stated.
- **Reinvented Wheel** — a hand-rolled implementation of something already provided, at any of three tiers: *this codebase already has it* (a second date formatter beside the one in `utils`, a hand-rolled retry where a decorator exists, a parallel HTTP wrapper), *the stdlib or the platform provides it* (`itertools`, `functools`, `bisect`, `dataclasses`; a picker component over `<input type="date">`, an app-level uniqueness check over a DB unique constraint), or *an already-installed dependency does*. → search the repo first, then reach outward in that order; a hand-rolled version beats a new dependency, but loses to anything already available. A function a typical developer wouldn't recognise still counts as provided — unfamiliarity is no reason to write the loop by hand. Don't DRY at all costs, though: where the existing helper doesn't fit the new case, a second clear function beats bending the first one into a parameterised knot.
- **Stateless Class** — a class whose instances hold nothing that outlives a single call: `__init__` stores its arguments, one public method reads them, and every call site constructs then calls once; or a class of only static methods used as a namespace. → make it a function taking those arguments, and a module for the namespace. State is the expensive thing — don't buy it to get a function.
- "Could [complicated thing|script|...] be a jq / bash / regex / ... ~one-liner?" → The complexity rarely pulls its weight.
- "Is this complicated because it's attacking the problem from the wrong perspective, or treating symptoms instead of causes?" → Not addressing the cause prepares worse symptoms and code/habits down the road.

*More style than smell -- increasing readability for human consumers / reviewers:*

- **Swiss-Army Tool** — one function, CLI, or module accumulating unrelated modes: a `--mode` flag selecting between behaviours that share no code, an options object whose keys are mutually exclusive, a helper doing three jobs depending on argument shape. → split into tools that each do one thing; a one-time operation needs no abstraction at all.
- **Needless Impurity** — a function that could be a function of its arguments but isn't: it mutates an argument, reads or writes module-level state, or reaches for the clock, filesystem, network, or randomness in the middle of its logic. → push the effects to the edges and leave the core computing its result from its inputs — it reads straight through and tests without setup. Not a finding where purity would cost more than it buys: in-place mutation of a large structure in a hot path, or a genuinely stateful protocol.
