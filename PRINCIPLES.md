# Workflow principles

Read this before changing a skill, a `CLAUDE.md`, or anything else about how the workflow runs, and when judging an upstream change (`pocock-sync`). Every principle here is a rule this workflow re-learned more than once; the citations are the evidence. Use it as a test on the change in front of you: which principle does it serve, which does it strain, and where does the rule already live, so it keeps one home. A change that strains a principle says so in its commit message.

The workflow's why: automate every check a machine can make, even at compute cost; human attention goes to design decisions and taste, at deliberate stations, never to flagging obvious slop.

Citations: a bare hash is this repo; `up:` is mattpocock/skills; `yt:<id> <mm:ss>` is a YouTube video; `workshop <h:mm:ss>` is `resources/full-walkthrough-workflow-for-ai-coding-matt-pocock.md`; `retro §N` is the skilltree retrospective (`agent/research/02-…`, gitignored); an author's name is a web post named in the research survey. Observations about one model or one harness are not principles; they live beside the mechanism they affect (dispatch's and code-review's model rules, the permissions skill).

## 1. Enforce, don't exhort

A rule enforced at a check beats a rule stated in prose. Three rungs, top first: the rule becomes a linter, a type, a test, a script, or a tool-level block, and the agent is corrected the moment it breaks it; the rule is pushed to a reviewer as a checklist against a finished diff; the rule is prose the agent reads while generating. Rung one is the target. A hook that injects a message is rung three in costume. A rule read while generating washes out under the pressure of finishing; the same rule read against a finished diff holds.

- **Put the rule at the moment of temptation, as a test the writer can run.** "Would a mechanism change force an edit here?" at the glossary step beat "no implementation details" at the top of the skill; "mechanical" is defined where the skip decision is made.
- **Grow rules only from observed failures, and prune them like code.** Every rule change in this repo cites the session where the old text failed; a bullet reaches an always-loaded file only when the failure keeps recurring. Exhortation bullets ("question assumptions", "think deeply") were deleted after being watched not firing in the exact scenario they target.
- **A script that does the thing beats a paragraph of prompt about it, and beats a tool definition carried in context.** Judgment stays prose; the deterministic protocol becomes a script whose echoed commands double as the by-hand recipe.

Evidence: eb47809 (style rules leave `CLAUDE.md` for code-review's smell baseline), c322cbf (post-commit review nudge), d09f56d and c3bec7f (exhortation bullets deleted), a8fc837 (a rule retired once the sandbox covered it), 581a2a6 (dispatch protocol into `dispatch-ctl`), a8c9a9a and 055fdd9 (the test at the point of decision), 4ed2207 and 6ee35a4 (rules from observed failures), c01c2a0 (allowlist tuned from real calls); up:cac4704 (smells as review baseline), up:8fa1886 (a `retro` skill feeding instruction updates); workshop 1:28:00 (standards pulled by the implementer, pushed to the reviewer), yt:3CSi8QAoN-s 01:08 (a `CLAUDE.md` line reduces the odds, a PreToolUse hook prevents), yt:llwTBpPqo9A 03:41 (a rule a hook already enforces is redundant in `CLAUDE.md`); Hashimoto (harness engineering: every mistake becomes a fix the agent cannot repeat), Ronacher (`gh` beats the GitHub MCP; scripts over tool definitions), Anthropic best practices (`CLAUDE.md` is advisory, hooks are deterministic).

## 2. State the goal at the right altitude

Say what the work is for; automate the precise parts; leave the rest to inference. Overspecified rules overfit the run they came from, carry their author's mistakes and contradictions, and the agent follows the wrong rule faithfully. A vaguer goal sometimes produces the better choice because the agent reasons from the destination instead of from a rule that was wrong. Contradictory rules burn reasoning on reconciling them. A required prose slot can always be satisfied with words, so it always is: keep only slots that cannot be padded. The one long precise list that works is the review smell baseline, and it works because a reviewer reads it against a finished diff (principle 1), never while generating.

- **Steer with positive instructions.** A prohibition names the banned behaviour and makes it more available; where the template already lacks the thing, the absence does the work. State the target ("report the finding and leave the fix to the maintainer") and the ban goes unspoken.
- **A principle has to be checkable to survive.** "Notice your silences" was dropped upstream a day after it landed as fuzzy legwork the agent cannot act on.

Evidence: e2d196c (800 enumerated allow rules replaced by a classifier that reads the whole command), d7b96b1 (no mandated reasoning effort), 7d5902d (the `Intent:` slot dropped), 5f31d98 and f470911 (bans rewritten as targets); up:e81f976 (TDD's step list deleted; the loop is already held), up:0847bb3 (the Negation failure mode), up:cb7db0e and 9d65390 (the estimate and its ban removed together), up:af6d692 (Negative Space dropped as not actionable); Anthropic context-engineering (prompts at the right altitude), GPT-5 guide (contradictions cost reasoning; soften the thoroughness rule and let the model decide), Pocock writing-for-agents (a skill built from one run over-indexes on it).

## 3. Every always-loaded word costs every turn

Material goes behind a pointer unless it applies to most sessions; the always-loaded file holds what shapes a first draft and what cannot be discovered by looking. A case that occurs once a year never belongs there; once a month, still not, perhaps a skill. Placement decides steering as much as length: the same text under-steered from `CLAUDE.md` and steered from the output style. The pointer's wording decides whether it fires; most under-use here was a description problem, and the fix was the trigger, not the body.

- **Use words the model already holds, and test a word for what else it primes.** Leading words (smell names, seam, fog of war, tracer bullet) carry their definition for free. "Branches" primed git-aware models to create git branches and became "modes". A harness's own names (its spawn tool, an agent-type name) are a no-op for the harness that owns them and a mis-prime for every other; describe the shape of the step ("spawn three subagents in parallel") and name a mechanism only where the neutral form demonstrably misfires, in one place. Verdict (2026-09-03): upstream's "Call the Skill tool with x" (up:d28dfdc) is rejected here; harness-neutral wording stands.
- **Name a harness in exactly one place.** The dispatch runner is the only file that names one; swapping the runner swaps the harness.

Evidence: up:4f6e25d (a 65-word `CLAUDE.md` edit cut to the one pointer line), eb47809 (what stays always-loaded: the four rules that shape a first draft), edaf49e (communication style moved to the output style because `CLAUDE.md` placement under-steered), ba1f634 (a long trigger description was pure context load), 4ed2207, 08bff5c and 507debe (trigger wording as the failure point), ef90c24 and 6ee35a4 (harness names dropped from skills), 581a2a6 (harness named once); up:cb51924 (branches → modes), up:14bfbbd and up:c0d6901 (tool names dropped), up:61accb0 (a description written as the pointer that decides when it fires); Pocock writing-for-agents (context load vs cognitive load; one context in ten pays load the other nine times), yt:9tmsq-Gvx6g 07:19 (an instruction budget of a few hundred, global to every use of the repo), yt:-uW5-TaVXu4 (lost in the middle; MCP servers bloat context); Ronacher (reinforcement after tool calls steers better than front-loaded instructions).

## 4. One home per fact

A restated fact is a cache; it goes stale unless the lookup is expensive. Code, config, `--help` and the directory layout are authoritative already; a document restating them rots on the first change. Skills are the single source of truth for process; a project artefact records only its deliberate deviations. A summary keeps the name and loses the mechanism, so the primary source stays reachable: prototypes kept in-tree, a handoff file over a compaction summary, a resumed worker told "continue" instead of a recap. Done work is retired by deletion or a tombstone; an artefact left looking live teaches a superseded design to every later reader.

Evidence: 1fd0dbe and retro §12 (a map note cached the old grilling rhythm and kept overriding the upgraded skill), 9f18fbb (`--help` documents the CLI, not the workflow around it), d8e4654 (a byte-copy of the validator drifted), 11f13c1 (a `CLAUDE.md` claim already false), 753bae3 (one home per fact lands in `CLAUDE.md`), retro §7 (prototype verdicts travelled five hops as winner-names; the ticket pointing at source produced the precise paragraph), da9e80b (retired prototypes kept as primary sources), 49d012b (handoff over compact; `/compact` removed from the ladder where up:fa1e322 keeps it as the floor), 0189f33 (restating to a resumed worker replaces better knowledge with worse), 91cc95c and d494777 (spec sweep and ticket retirement on resolve); up:d4e8664 (the cache leading word), up:3314257 (25 hand-copied install commands drifted), up:9272935 (the map is an index, not a store), up:c66bdee (a retired skill deleted, the changeset naming its replacement); yt:9tmsq-Gvx6g (`/init` writes facts the file system already states, and file references that rot), yt:Ah9p7v7nJWg 06:16 (research lives one sprint; stale research steers wrong, hence `agent/research/` gitignored, f994656), workshop 1:23:29 (an old PRD found a month later is doc rot).

## 5. Deliver through artefacts written for a cold reader, carrying the why

The chat and the return channel are not durable; a file is there whether or not the agent ended cleanly. Every artefact is read by someone without this conversation: it states what is, and the narrative, the decisions against, and the change story go to the commit message, the ADR, or the spec's out-of-scope section. The destination and the reason come before the how: an agent that holds the what without the why cannot suggest alternatives; a handoff without a stated purpose is refused. If a thing cannot be said in plain words, it has not been decided; roughly half the agent-coined phrases in one retrospective hid an unmade decision.

Evidence: 0b37423 and 85674fc (a named subagent's report arrived as an empty ping; the fix names the file it writes), ec262ac and c42a5c0 (reviewers ended their turn holding the report; now delivered to a file), f470911 (a worker's chat is read by nobody; the ticket is the durable channel), 351ce7a (a worklog created up front so emptiness is a reading), 61961f1 and 753bae3 (the recurring slop is conversation residue and cached facts, not style), b905ec7 (a ticket that under-describes its work misleads the next reader), 507debe (commit bodies answer "what did the human want?"), 7ca2f5c (a handoff states its purpose); up:86b07d1 (attributed opinion dates when the position moves), up:da2cb7d (change narration belongs in the changeset), up:14780a1 (a multi-way branch is a table, never a paragraph), up:53c6219 (destination as the first thing charted); workshop 58:08 (negative decisions live in out-of-scope), yt:hX7yG1KVYhI 05:28 (without the why, no alternatives), retro §11 (fourteen "what does this mean" queries in one session).

## 6. Facts are the agent's to find; decisions are the human's to make

Silence is not agreement; an unconfirmed decision stays marked. Every claim carries provenance, and the agent's negative claims about the environment ("there is no test suite") are as unverified as its positive ones. A recommendation followed by the user moving to another topic is not a ruling; a casual go-ahead ratifies proceeding, not the frame. An agent-written statement of its own intent is self-certification. Options put to the human must all be ones the agent would defend; one live option is not a question. The friction a worker hits is filed by the dispatcher after the user has ruled, because the worker is the party least able to judge whether it is ticket-worthy. Grilling is where alignment happens (the mx README says how), and the spec written there is the highest-leverage line to review: a wrong line of code is one wrong line, a wrong line in a plan is hundreds.

Evidence: 7f6dfb0 (consent section; Assumptions block for the user to ratify), retro §4 (a recommendation reached four artefacts as a decision; the audit's findings go into the artefact, not through the human as a message), ddafe22 (evidence settled an option list without asking whether the shared premise held), c50f500 (one live option is not a question), 7d5902d (`Intent:` dropped as self-certification), 8caba61 (workers file nothing; the dispatcher does), 1405618 (models named by the user, never defaulted), 474a0e2 (an upstream issue needs an explicit yes); up:e5932a7 (wayfinder grilling itself; facts split from decisions), up:0e9a072 (a confirmation gate); yt:9VNG0h4pLh0 (training rewards guessing over admitting uncertainty; "use your search tool" turns a parametric claim into a contextual one), yt:llwTBpPqo9A 05:00 (ask it to steel-man the opposite; "refreshingly minimal" is this year's "you're absolutely right"), yt:hX7yG1KVYhI 28:39 ("no test harness" was false); Horthy (a bad line of a plan leads to hundreds of bad lines of code), Ball (the agent does not make architectural decisions).

## 7. Judge in front of a render

Humans judge far better in front of a render than in the abstract. A blank answer means the question was posed backwards: build the artefact and let them criticise it. A prototype overturned a grilled ticket and an ADR within a day; the same person who was blank on "what goes in the sidebar" produced publishable criticism in front of a render. The leap from spec to production code is large and from working prototype to production is small. QA per landed slice is where taste is imposed, and it stays manual: automate the idea, the planning and the QA and the result lacks taste. Front-end feedback loops are visual; an agent without a browser is flying blind.

Evidence: retro §5–6 (grilling depth tracked arguability, not importance), 7f6dfb0 (orient routes user-visible surfaces to prototype-first), 61f3007 and afb0928 (`/mx:show`), e065e9b (diffview as the default review surface), 2b34e11 (grilling delivers a vetoable whole); up:d627460 (the prototype is a primary source); yt:n0VhIVtviC0 (some questions can only be answered by prototyping), workshop 1:12:35 (QA is where taste is imposed), yt:hX7yG1KVYhI 38:10 (a two-button menu became a checkbox only once seen; git edge cases surfaced only in QA), yt:DNqsMXH6Eog 06:00 (the AI cannot see what it is building).

## 8. Fresh context per unit of work

The window has a smart zone; reasoning degrades from roughly a third of it used, regardless of the advertised size, and an agent cannot introspect the degradation, so the rule is stated as a fraction. An author is the wrong reviewer of its own diff: a reviewer sharing the implementer's window reviews in the dumb zone, and a model is reluctant to change code sitting in its own context. Repeated compaction leaves sediment from earlier conversations; a handoff file is a deliberate reset that can be read and edited before it seeds the next session. A different model family reviewing than the one that wrote is the strongest form. Open (2026-09): whether ticket-sized fresh workers or one long session produce more coherent code; fresh workers stay, and principle 9's coherence test plus the review session carry the objection.

Evidence: 49d012b (smart zone as a fraction; `/compact` off the ladder), d7c7120 and 04cfa46 (a different family reviews; fresh-context reviewers kept when the default reverted), 1405618 (review model chosen per diff size), 7ca2f5c and f3970c8 (a handoff states what the next session will focus on); up:fa1e322 (phase-boundary tree: continue, clear, handoff, subagent), up:2e64732 (fail-fast before spawning reviewers); workshop 0:03:12 (smart zone, dumb zone, Memento), workshop 1:05:43 (clear the context and the reviewer reviews in the smart zone), yt:M6mYodf0dJM 15:45 (agents are bad at improving code they just wrote), yt:dtAJ2dOd3ko (the handoff document as a DIY subagent that crosses harnesses), yt:-uW5-TaVXu4 06:22 (clear should be the default); Ball (run `git diff` to see the code someone else wrote), Anthropic 4.6 guide (fresh context plus filesystem discovery beats compaction).

## 9. Slice along seams that already exist

A unit of work that spans an owner boundary or a hub file is a serialisation signal, not a scheduling problem; the per-ticket isolation that keeps workers fresh is what produced the incoherence when sixteen of twenty-nine tickets conflicted on one file. Vertical slices, each a tracer bullet demoable when it lands; the model codes horizontally by default. The ticket breakdown is reviewed for its shape (slice count, size, verticality), which is cheap and whose failure is visible; the text is not. A property with no user story gets no slice, so properties are stated in the spec. Deep modules: design the interface, delegate the implementation, and test boundaries follow module boundaries.

Evidence: retro §10 and 621ce5d (hub-file conflicts, with a runnable demo), 7f6dfb0 (dispatch's coherence test: shared surface means a serial worker; cross-cutting capabilities as a slicing exception), 8f70559 (cross-feature edges serialise), retro §2 (Properties section in the spec), 34f8da6 (a reproducible setup target is what lets workers open a worktree on any host); up:a0329ba (wide refactors sliced by expand–contract); workshop 0:41:37 (vertical slices; the breakdown is the artefact worth reviewing), workshop 1:14:00 (deep modules as gray boxes), yt:hX7yG1KVYhI 30:19 (too small a ticket pays the cost of an agent start; two slices merged).

## 10. Verify against the live system, and make every failure state distinguishable from success

Documentation describes what the author believed; the live system is the authority, and a rule written from reading rather than running is wrong often enough that it is written after the run. Feedback loops are the ceiling on agent output: without them the agent codes blind, and the rate of feedback is the speed limit. Every state the machinery can be in needs its own reading: a killed pane that still says running, an absent worklog versus an empty one, a subagent ceiling that looks like a crash. Treat causes, not symptoms: a hazard that moved rather than went away is a workaround. If it has not been seen running, it is not a working system.

Evidence: d8e7b5d (the permission scanner documented the same wrong model as the docs; probing a live session turned 7445 phantom findings into 5876 real ones), afb0928 and 72ef6ba (a render loop caught two bugs in the guide's own text), c1764f4 (a rule verified in the browser before being written), 0687f96 (`tmux wait-for` verified unreliable; the pane probe becomes the authority), ba0f663 (a third state, `gone`), 351ce7a (absent versus empty), 8a564d5 (a ceiling that reads like a crash), aab7abf and 8937f1c (symptoms versus causes); up:8a475c4 (a refactor whose removals landed and replacements did not), up:42a5b70 (an ADR records what was verified, on which version, and what was not); Pocock writing-for-agents (settle a disagreement by running the document; duplication is the sign it was never tested), workshop 1:09:53 (the quality of your feedback loops is the ceiling), yt:v4F1gFy-hqg 10:42 (the rate of feedback is the speed limit), yt:_IK18goX4X8 (an agent marked features complete without testing until told to test as a user would); Willison (if you haven't seen it run, it's not a working system).

## 11. Isolate what runs unattended, and write its prompt for a machine

The human's decisions are front-loaded into grilling; everything that can run without a human runs without one; what needs judgment is surfaced afterwards in the form best suited to judging it (principle 7). Permission prompts and unsandboxed workers both put the human back into steps that should not need one. The isolation is the permission boundary: a worker installing a system dependency is doing unreviewed work outside its worktree on a machine nobody is watching, so an isolated host gets permissions bypassed and no credentials. The prompt is written for a reader with no conversation: the user's `CLAUDE.md` describes a conversation the worker is not in and tells it to ask questions it cannot ask. Shared checkouts never switch branch; nothing is committed with `-a`; scratch state is namespaced per feature and per repo. Reversibility gates autonomy: local and reversible runs freely; destructive, shared, or ship-shaped waits for the human.

Evidence: f470911 and 43eeee8 (the worker prompt; auto-memory off), a5c41ab (the blast-radius rule), 21d17ae and 5c96574 (no credentials on the worker user), 4527ead, ed001b7 and 4718b33 (never switch the shared checkout; hunk-stage around foreign edits), 5676532 and 11f13c1 (per-feature and per-repo namespacing after two dispatchers collided); workshop 0:55:12 (AFK loops run in a Docker sandbox; a worktree per issue), yt:E5-QK3CDVQM 00:35 (unsandboxed yolo mode deletes home directories), yt:yv8VZpov8bk 05:47 (a worktree cut from main pushed to main by default); Codex and Anthropic docs (reversibility as the autonomy gate).

## 12. Scale the process to the work

A step (grilling, review, a map) is skipped only when the change was dictated or needed no judgment; "it's small" and "it's only prose" are not reasons, because in this setup prose in skills and docs is the logic. Grilling triggers proportionally on any intent that is not fully mechanical: depth, not volume. A map is for an idea that will not fit one session; reaching for it on well-scoped work is the common mistake, and no fog means no map. Optimise only the artefacts someone reads: the "sacrifice grammar for concision" line left `CLAUDE.md` once its author stopped reading plans. Ticket sizing is two-sided; too small pays an agent start per slice.

Evidence: 9426de6 and 055fdd9 (the review gate's skip criterion), 04cfa46 (light review for specless work), 507debe and 137a3db (proportional grilling); up:ad99c73 and up:9b43c33 (no fog, no map), up:e74fee8 (over-reaching for wayfinder), up:b56795b (a hard cap on grilling questions rejected); yt:WNx-s-RxVxk 09:49 (when you know the codebase, make the change yourself), workshop 0:48:23 (the concision line dropped), yt:hX7yG1KVYhI 30:19 (two slices merged as too small).

## 13. Own the stack

Observability over the whole planning stack is what turns "this isn't working" into a fix; a workflow whose pieces someone else owns cannot be tuned. The agent is the tactical programmer; the strategic level (architecture, what to build, when to invest in design) is the human's, and the agent is treated like a delegate on the team with unusual constraints. Twenty-year-old books already verbalised the practice in English (Brooks, Fowler, Ousterhout, the Pragmatic Programmer, Shape Up) and are the richest prompt material; bad code is the most expensive it has ever been, so design is invested in daily. One ship mechanism: unpushed and untagged edits exist nowhere.
